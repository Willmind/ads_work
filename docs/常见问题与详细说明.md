# Mix Web 部署工具：常见问题与详细说明

适用版本：0.2.3（macOS）

面向团队使用者，无需项目源码或开发环境。

## 1. 这个工具能做什么

通过 Jumpserver 登录目标服务器，查看并搜索 Git 分支，切换服务器项目分支并拉取代码。

操作对象是服务器上的仓库，不是你电脑上的代码。

> “切换并拉取”目前只负责更新 Git 代码，不会自动安装依赖、构建项目、重启服务或检查网站是否正常。是否还需这些操作，应按项目的发布流程确认。

## 2. 使用前准备

- M 系列芯片的 Mac，macOS 13 或更新版本。当前安装包不支持 Intel Mac 或 Windows。
- 能访问团队 Jumpserver 的网络环境；如果团队要求内网或 VPN，请先连接。
- 个人 SSH 用户名，以及本人获授权使用的 PEM 私钥文件。
- 管理员提供的 SSH 主机、端口、服务器项目目录和两次菜单选项。
- 对目标服务器和仓库有相应权限；远程 Git 操作需要具备指定命令的 sudo 免密权限。

应用调用本机的 `/usr/bin/ssh` 和 `/usr/bin/expect`。使用者不需要安装 Xcode、Swift 或 Node.js；若系统缺少这些命令，请联系工具维护者。

## 3. 安装与打开

1. 从团队可信渠道获取 `Mix Web 部署工具.app` 的 ZIP 压缩包。
2. 双击 ZIP 解压，将 `Mix Web 部署工具.app` 拖入“应用程序”文件夹。
3. 如果旧版本正在运行，先彻底退出旧版本，再打开新版本。

### 首次打开出现安全提示

当前版本采用本地临时签名，尚未使用 Apple Developer ID 签名及 Apple 公证，首次打开可能被 macOS 拦截。

仅在确认安装包来自团队可信来源、没有被篡改后，尝试以下操作：

1. 先尝试打开应用。
2. 进入“系统设置 → 隐私与安全性”。
3. 若出现“仍要打开”，点击并按系统提示确认。

公司管理的 Mac 可能不允许此操作，需要联系 IT。若提示应用包含恶意软件或已损坏，应停止打开并联系维护者核查，不要关闭系统安全保护或运行网上的绕过命令。[Apple 官方说明：在 Mac 上安全地打开 App](https://support.apple.com/zh-cn/102445)

## 4. 首次配置

打开“连接设置”，按管理员提供的信息填写。下表均为说明或虚构示例，不是可直接使用的连接信息。

| 字段 | 如何填写 |
| --- | --- |
| SSH 主机 | Jumpserver 的 SSH 地址，不要填写网页 URL，也不要添加 `https://`；例如 `jump.example.invalid`。 |
| 端口 | 填写实际 SSH 端口，不要直接沿用默认值。 |
| SSH 用户 | 填写你自己的 Jumpserver SSH 用户名。 |
| PEM 私钥 | 点击“选择…”选取本人获授权使用的 PEM 文件。 |
| 项目目录 | 填写目标服务器上的 Git 仓库绝对路径，例如 `/path/to/project`，不是本机代码路径。 |
| 菜单选项 | 按 Jumpserver 实际交互顺序填写两次选择；不同用户看到的选项可能不同，不要直接照抄他人配置。 |

配置会自动保存在当前 Mac 用户的本机偏好设置中，无需单独点击保存。配置完整后默认折叠，点击“展开修改”仍可修改主机、用户、端口、私钥路径等字段；操作执行期间字段暂时不可编辑。

> 应用只保存私钥的文件路径，不会把私钥复制进应用。请将私钥放在稳定、安全的位置；移动或删除文件后，需要重新选择。

填写完成后，先点击“检查连接”。它只验证能否登录到目标服务器 Shell，不验证项目目录、Git 权限或代码状态。连接成功后，再尝试加载分支。

## 5. 日常使用

### 第一步：加载并选择分支

1. 点击“选择分支”，打开搜索弹窗。
2. 列表为空时，点击弹窗中的“加载分支”；主界面的“刷新分支”作用相同。
3. 输入分支名的一部分进行搜索，点击匹配项完成选择。也可以在主界面直接输入准确的分支名。
4. 如果找不到刚创建的分支，点击“同步远程”，完成后再次搜索。

| 操作 | 实际作用 | 是否切换工作区分支 |
| --- | --- | --- |
| 选择分支 / 搜索 | 打开列表、筛选并设置本次目标分支，本身不执行远程 Git。 | 否 |
| 刷新分支 / 加载分支 | 连接服务器，读取仓库已有的 `origin` 远程跟踪分支记录，不执行 `git fetch`。 | 否 |
| 同步远程 | 连接服务器，执行 `git fetch --prune origin`，更新远程跟踪记录后读取列表。 | 否 |
| 切换并拉取 | 同步远程、检查工作区、切换到目标分支并拉取代码。 | 是 |

分支列表仅保存在应用当前运行的内存中，重启后需要重新加载。修改连接设置会清空旧连接的列表，需要重新加载。

### 第二步：核对目标并执行

1. 核对连接设置，确认是正确的服务器、菜单选项和项目目录。
2. 确认目标分支，点击“切换并拉取”。
3. 阅读确认弹窗，确认后再执行。弹窗中的项目路径等信息不要直接截图外发。

工具按顺序执行以下步骤（下面为原理说明，无需手动输入）：

```text
连接 Jumpserver → 进入目标服务器项目目录
→ 同步远程分支
→ 检查服务器工作区
→ 切换目标分支
→ 拉取代码
→ 读取提交号并显示结果
```

远程 Git 使用 `sudo -n`，不会交互式索要 sudo 密码。若工作区存在未提交修改，会停止切换；拉取采用 `git pull --ff-only`，不会自动生成合并提交或强制覆盖代码。

### 第三步：核对结果

成功后会显示完成状态、目标分支、提交号、完成时间和耗时。请按项目流程继续验证服务是否正常，不能仅凭“拉取完成”判断业务已上线。

操作失败会显示对应阶段和错误说明。点击“复制脱敏日志”可收集反馈信息；当前日志会在开始下一次操作时清空，需要反馈时请先复制保存。

> “停止”会中止本机连接流程，但不等于回滚，也不能保证远程正在执行的命令已停止。此前的切换或拉取可能已经生效，重试前应核对服务器实际分支、提交和运行状态。

## 6. 常见问题

### 为什么刷新分支也要等一会儿？

刷新虽然不执行 `fetch`，仍需要建立 SSH 连接、经过 Jumpserver 两次菜单选择，并进入目标项目目录。网络、认证和菜单响应都会影响耗时。“同步远程”额外访问 Git 远端，通常需要更多时间；以当前显示的阶段为准。

### 为什么“选择分支”里没有内容？

第一次使用、重启应用或修改连接后需要重新加载。先点击“加载分支”；找不到新分支时再点击“同步远程”。当前只列出 `origin` 的远程跟踪分支，不列出其他远端或仅存在于本地的分支。

“选择分支”入口可以打开；有操作正在执行时，弹窗会显示进度，暂时不允许加载或选取分支。

### 为什么检查连接成功，读取分支却失败？

SSH 连接成功不代表项目路径和 Git 权限正确。根据具体提示处理：

- **不是 Git 仓库**：核对目标服务器和项目目录，目录应指向正确仓库。
- **sudo 需要密码或没有授权**：请管理员确认当前 SSH 用户对所需 Git 命令的免密授权；不要向应用填写或向他人发送密码。
- **仓库属主不匹配**：请管理员核对仓库属主与 Git 信任配置，不要盲目将所有目录加入信任列表。
- **文件访问被拒绝**：请管理员检查目标目录和仓库文件的访问权限，不要将目录统一改为开放权限。
- **Git 格式参数不支持**：确认已退出旧版本，并打开 0.2.3 或更新版本。
- **其他退出码**：将失败阶段、退出码和经检查的脱敏日志发给维护者。

### 提示工作区有未提交修改怎么办？

先请代码负责人确认修改来源并按团队流程处理，再重试。工具不会自动删除、覆盖或暂存服务器上的修改，不要为了继续发布直接强制重置仓库。

### `git pull --ff-only` 失败怎么办？

可能是网络、Git 远端权限或分支历史分叉等问题。请管理员结合失败阶段核查，不要直接改成强制拉取。此时分支可能已经切换成功，因此应先检查实际状态。

### 私钥需要口令，或登录需要额外输入怎么办？

当前工具没有交互式口令、密码或验证码输入界面。若出现此类提示，请联系管理员确认适配方式，不要为了使用工具擅自去掉私钥保护或改用他人的账号。

## 7. 更新和分享

更新时先退出应用，在“应用程序”中替换为新版本，再重新打开。同一 Mac 用户下，正常替换应用会保留原有连接配置；分支列表需要重新加载。建议只保留一个常用副本，避免误开旧版本。

发给同事时：

1. 在 Finder 中右键 `Mix Web 部署工具.app`，选择“压缩”。
2. 将 ZIP 和本说明文档一起发给同事，无需发送项目源码。
3. 同事自行配置个人账号和私钥，并核实自己的服务器访问权限。

发送应用本身不会带上你保存在本机的连接配置。不要把 PEM 私钥、个人配置备份、原始 SSH 日志或包含真实连接信息的截图放进分享包。

日志会隐藏已配置的连接字段和常见地址、路径，但脱敏不能保证覆盖所有内部信息；分支名、提交号或业务文字也可能敏感。分享日志前仍需人工检查，并按团队要求选择接收范围。

## 8. 问题反馈

向维护者提供以下信息即可，不要提供私钥或密码：

- 应用版本，以及 Mac 芯片类型和 macOS 版本。
- 点击了哪个按钮、失败停在哪个阶段。
- 完整错误提示与人工检查后的脱敏日志。
- 是否仅某个分支失败、此前是否执行过“停止”。

真实主机、账号或项目目录如确需核对，请通过团队批准的私密渠道提供，不要粘贴进公开问题单或代码仓库。
