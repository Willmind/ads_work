# Mix Web 部署工具

一个仅面向 macOS 的 SwiftUI 小工具，支持通过 Jumpserver 切换服务器 Git 分支，以及打包本地 mix_client 并替换 AdsPower 的主 JS。

## 安全原则

- PEM 私钥始终保留在应用外部，应用只保存文件路径。
- 分支名、SSH 地址和项目路径均经过白名单校验。
- 服务器工作区存在未提交修改时，停止切换分支。
- 使用 `git pull --ff-only`，不自动制造合并提交。
- 使用 `sudo -n`，应用不会请求或保存远程 sudo 密码。
- 日志不转发 SSH 命令、登录横幅、资产菜单和 Shell 提示符；连接字段与常见地址、路径会再次脱敏。复制按钮复制的是同一份脱敏日志。

## 构建

当前 Mac 已安装 Swift Command Line Tools，无需完整 Xcode 即可构建：

```bash
chmod +x scripts/build-app.sh
./scripts/build-app.sh
```

生成结果：

```text
dist/Mix Web 部署工具.app
```

## 首次配置

- Jumpserver：填写团队提供的 SSH 主机和端口。
- SSH 用户：填写个人的 Jumpserver 用户名。
- 项目目录：填写服务器上的 Git 仓库绝对路径，例如 `/path/to/project`。
- Jumpserver 菜单：按照实际交互流程填写两次菜单选项。
- PEM：通过文件选择器指定当前 Mac 上的私钥文件。

仓库不包含真实连接信息或私钥。所有配置都在应用界面填写，并保存在当前 Mac 用户的 `UserDefaults` 中。

配置完整时，“连接设置”默认折叠，点击“展开修改”可以继续修改主机、用户、端口、私钥路径和项目目录。首次使用或配置失效时会自动展开。执行期间暂时禁用字段，避免本次操作的目标发生变化。更新应用保留原有本机配置。

修改连接后会清空旧服务器的分支列表；修改分支或连接后会清除旧成功状态。

## 使用顺序

1. 点击“检查连接”。
2. 点击“选择分支”打开搜索弹窗。列表为空时可在弹窗内“加载分支”或“同步远程”，也可在主界面直接输入已知分支。
3. 点击“切换并拉取”，确认后执行。

“刷新分支”只读取服务器上现有的 `origin` 分支记录，不执行 `fetch`；仍需要建立 SSH 连接并进入 Jumpserver。若找不到新建分支，点击“同步远程”，执行 `git fetch --prune origin` 后重新读取列表。两种操作均不切换工作区分支。

“选择分支”入口始终可打开；执行操作期间弹窗显示当前进度，完成后允许选择。分支列表仅保存在本次运行的内存中，重启应用后需要重新加载；加载失败时弹窗提供错误说明和重试入口。

分支读取使用基础 `%(refname)` 格式，避免依赖服务器 Git 的 `strip` 格式修饰符。读取失败会区分非 Git 仓库、sudo 授权、仓库属主及文件权限等常见原因；未识别的错误保留退出码，不显示包含内部信息的原始诊断。工具不会自动修改服务器权限或 Git 信任配置。

“切换并拉取”的远程操作顺序为：

```text
git fetch --prune origin
git status --porcelain
git checkout <branch>
git pull --ff-only origin <branch>
```

执行区按实际操作显示阶段；失败会停留在对应步骤，成功时显示完成时间和耗时，切换并拉取还会显示目标分支和提交号。“停止”会断开连接，已经执行的远程步骤不会撤销；请核对服务器状态后再继续。

## 本地客户端打包与替换

在“本地客户端打包”中选择本地 `mix_client` 仓库根目录，以及 AdsPower 的 `cwd_global/lib` 目录，点击“打包并替换”。默认路径根据当前用户主目录生成，两个路径均可修改并独立保存在本机，不需要先配置 SSH。

执行顺序：检查本地当前分支 → `npm run buildLb` → 校验本次主 JS → 备份原文件 → 原子替换 `lib/main.min.js`。包含本地未提交修改，不执行分支切换或拉取。打包时请不要在其他工具中修改源码或切换分支；如果分支或提交发生变化，工具会停止替换。

同版本的 `版本号_main.min.js` 会重新生成，历史版本临时移开并在打包后恢复；不会通过修改时间猜测哪个文件是新产物。打包失败、没有产物、多个主 JS 或空文件都会停止替换并恢复旧主 JS 产物。已有的 `lib/main.min.js` 会保存为同目录 `main.min.js.backup-时间-随机编号`，每次保留独立备份。复制文件后校验 SHA-256，目标文件通过同目录临时文件和原子重命名更新。

界面显示阶段、结果弹窗、实际分支、产物名、目标及备份路径，并可展开或复制打包日志。替换后重新启动 AdsPower 使用新 JS。需要恢复时，退出 AdsPower，将所需备份复制为 `main.min.js`。

支持常见 Homebrew 路径和 nvm 的 default Node.js 版本。构建超时为 15 分钟，“停止打包”会结束 npm 及构建子进程，未完成的构建不会用于替换。为避免多个窗口同时操作同一项目，构建期间使用 `.ads-work-build.lock`；应用异常退出后若提示锁已存在，请确认没有构建进程，再手动删除该锁文件。

## 本地验证

```bash
zsh scripts/check.sh
```

自检使用临时本地 Git 仓库、内存配置和模拟交互终端，覆盖生产分支命令、格式兼容性模拟、嵌套分支名、分段 UTF-8 输出、日志脱敏、刷新跳过 fetch、远程同步、空列表、错误分类、工作区有修改、拉取失败、完成标记及停止行为。还会通过临时 Node.js 项目执行真实 `npm run buildLb`，验证带空格路径、同名及相同内容产物、备份、历史产物恢复、构建失败、产物缺失或歧义、分支变化、停止子进程、超时及构建锁。不会启动真实 SSH、执行真实远程 Git，或访问用户私钥、实际 AdsPower lib 与应用配置。

首次使用建议只执行“检查连接”。若 Jumpserver 菜单流程发生变化，可根据当前阶段和错误提示检查连接配置。
